# Independent checkpoint protocol v1

Status: active process requirement; real-scene execution is blocked pending verified external products and a frozen split.

Before a held-out scene can support a public claim, two reviewers who did not tune the route independently review the evidence bundle. Each records: source/reference identifiers and checksums, correspondence decision, covariance or control uncertainty, exclusions and reason, and any disagreement. Neither reviewer may replace unknown uncertainty with zero. The machine-readable contract is `schemas/independent-checkpoint.schema.json`; `benchmarks.scripts.checkpoints.load_checkpoint_record` validates it against the immutable report it names. The report carries a content-hashed frozen route/parameter snapshot and a content-addressed parameter-fit provenance record. The fit record binds every fitting input to the immutable source manifest and permits development/validation inputs only; reviewer overlap or held-out tuning use is rejected.

Disagreements are retained in the checkpoint record and referred to a third reviewer for resolution. The resolution must name the original decisions; it does not erase them. A withheld scene may be evaluated only after route parameters are frozen from development and validation evidence. It is never training, calibration, threshold-selection, or fallback-selection data.

The checkpoint records an accept, exclude, or unresolved decision. The validator derives disagreement from the two reviewer decisions; disagreement requires an independently resolved final status. Excluded and unresolved scenes remain in the run report's `held_out_checkpoint_population` denominator and are visible in the claim ledger scope and limitations, but cannot authorize a public quantitative claim. A report ID is content-addressed (`brr-sha256-...`); reviewers cite that ID rather than mutable filenames. An active claim ledger must resolve both that report and an accepted linked checkpoint from explicit evidence directories.
